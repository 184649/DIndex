# 既存プロファイルを新しいプレビュー用プロファイルへコピー

この補助スクリプトは任意実行です。インストーラーから自動実行されません。新規利用者には不要です。既存環境の更新・プレビュー確認では、元のプロファイルとアプリを残し、別の新しいプロファイルへコピーできます。

## 実行前

- Windows とインストール済み PowerShell 7.2 以降（`pwsh`）が必要です。Windows PowerShell 5.1 は対象外です。スクリプトはツールをインストールしません。
- DIndex、DHub、タスクトレイの常駐インスタンス、両アプリのアップデーターをすべて終了します。コピー中は起動しないでください。プロセスを自動終了することはありません。
- `Source` は実際の保存データがあるディレクトリを明示します。EXE のあるフォルダーとは限りません。既定の旧プロファイルは通常 `%LOCALAPPDATA%\DIndex` です。別の保存先を指定していた場合は実際の保存先を確認してください。
- `Destination` は存在しない新しいディレクトリに限ります。空の既存ディレクトリも拒否します。すでに起動して作られたプレビュープロファイルは削除・統合せず、別の保存先を選んでください。
- `BackupDirectory` はバックアップを置く別ディレクトリです。各実行で一意の子ディレクトリを新規作成します。3つのパスは同一・親子関係であってはいけません。
- 保存先とバックアップ先の親ディレクトリは先に用意してください。必要な空き容量は、完全バックアップと取り込み分の合計以上です。
- 対象はローカル固定ドライブです。UNC、デバイスパス、相対パス、`.` / `..`、末尾の空白・ドット、`~` を含む曖昧な短縮パス、ジャンクション・シンボリックリンク・その他の再解析ポイントは拒否します。NTFS の代替データストリームがあれば、省略せず停止します。

## 実行例

リポジトリのルートで、実際の保存先を確認してから実行します。既存のプロファイルに上書きしてはいけません。

```powershell
pwsh -NoProfile -File .\scripts\Copy-LegacyProfile.ps1 `
  -Source "$env:LOCALAPPDATA\DIndex" `
  -Destination "$env:LOCALAPPDATA\DIndex-Preview" `
  -BackupDirectory "$env:USERPROFILE\DIndex-MigrationBackups"
```

`Source`、`Destination`、`BackupDirectory` はすべて必須です。既定のプレビュープロファイルがすでにあれば、存在しない別の確認用ディレクトリを選びます。DIndexでは確認用起動の前に `DINDEX_DATA_DIR` 環境変数でその保存先を指定できます。

## コピーの保証と制約

1. プロセス一覧の確認に失敗した場合も停止します。既知のアプリ名、旧 `ShortcutList.exe`、アップデーター、対象アプリをホストする `dotnet.exe` を保守的に検出します。判別不能な `dotnet.exe` も停止理由です。任意に改名された古い EXE や、すべての外部ツールを検出できるわけではありません。
2. 元ファイルは読み取り専用で開き、書き込み・削除を共有しないハンドルを処理完了まで保持します。元のファイルの一覧、空ディレクトリ、サイズ、SHA-256、更新時刻を取得します。元フォルダーにロックファイルを書き込みません。
3. ソース内の通常ファイルをすべて `snapshot` にコピーします。古いキャッシュ、診断ログ、存在するロックの痕跡も完全バックアップには残します。ファイルの内容とパス・ディレクトリ構造のスナップショットであり、ACL、所有者、作成時刻、属性、ハードリンク関係を復元するシステムバックアップではありません。代替ストリームや再解析ポイントは未保存のまま成功扱いせず拒否します。
4. バックアップの一覧・全ファイルハッシュを元の取得値と照合し、ソースを再走査して変更がないことを確認します。追加・削除・名前変更・内容や更新時刻の変更を見つけたら停止します。途中までのバックアップも自動削除しません。
5. 検証済みバックアップから必要なデータだけを、保存先と同じ親ディレクトリにある一意のステージングディレクトリへコピーします。JSON を再シリアライズせず元のバイト列を保持します。アプリの起動、復旧処理、外部リンクの実行、参照先フォルダーの取り込みは行いません。
6. ステージングの全ハッシュ、完全バックアップ、ソースの再照合とプロセス再確認を終えてから、同じ親ディレクトリ内の名前変更で新規の `Destination` として公開します。既存ディレクトリへの統合・削除・置換はしません。確認後に保存先が作られても名前変更は失敗し、既存データを残します。

同時に動く悪意のあるプログラムによるディレクトリ置換や、電源断まで防ぐトランザクションではありません。アプリ・同期・編集ツールを終了した静かなローカル環境で実行してください。名前変更の原子性は「完成したフォルダーだけを公開する」ためのものです。突然のストレージ障害に対する独立したバックアップは別に必要です。

## DIndex の対象

- 必須の `settings.json` だけを新プロファイルへコピーします。古い `index-cache.tsv` は絶対に持ち込みません。初回起動後に新しい版でインデックスを再構築してください。
- JSON は UTF-8（BOM可）、オブジェクトのルート、重複/大小文字が曖昧なキーなし、コメント/末尾カンマなしを要求します。
- `SearchRoots` と `ExcludeFolderNames` は空白文字列/nullを含まない文字列配列、`SearchPath` と `IncludeDirectories` は真偽値、`ResultLimit` は1～100,000の整数です。既知のキーは上記の正確な表記を要求します。
- `SchemaVersion` は省略可能です。省略した従来設定と整数0/1を受理し、未来のスキーマ、不正型、負数を拒否します。未知の追加プロパティはそのまま保持します。
- `settings.json.bak` があっても自動復旧しません。現行 `settings.json` の欠落/破損は停止理由です。診断ログ、更新用ディレクトリ、バックアップ、キャッシュ等は完全バックアップだけに残します。

## サイズ上限

既定は以下です。上限超過は変更せず停止します。実データ量を確認した場合だけ明示的に増やしてください。

| 引数 | 既定値 | 用途 |
| --- | ---: | --- |
| `MaxFiles` | 10,000 | 元プロファイルのファイル数。総エントリー数はこの4倍まで |
| `MaxBytes` | 2 GiB | 元ファイル合計 |
| `MaxFileBytes` | 512 MiB | 1ファイル |
| `MaxJsonBytes` | 32 MiB | 解析する各JSON。最大指定256 MiB |

ファイル数上限は最大100,000です。大量のファイルでは読み取りハンドルやディスク空き容量の制限で停止する場合もあります。上限を増やすためにキャッシュや履歴を自動削除する処理はありません。

## 結果と失敗時

成功時に `Destination` と `Backup` を表示します。バックアップ実行ディレクトリには、`snapshot`、`manifest.json`、`SNAPSHOT_VERIFIED.txt`、`IMPORT_SUCCEEDED.txt` が残ります。失敗時には可能な限り `IMPORT_FAILED.txt` を残し、バックアップとステージングのパスをエラーに表示します。

- `SNAPSHOT_VERIFIED.txt` がないバックアップは途中までの可能性があります。完全な復元元だと判断しないでください。
- `SNAPSHOT_VERIFIED.txt` は元の全バイト列のコピー検証結果です。JSON の業務上の正しさ、過去のバックアップの健全性を保証するものではありません。
- 失敗後は出力先をアプリで開かず、元データとバックアップを保管してエラー原因を確認してください。原因を解消して再試行する場合も、新しい保存先を選びます。
- このヘルパーには復元・上書き・マージ・削除機能がありません。元の通常版を再開する場合は元のプロファイルを引き続き使います。プレビューで行った変更は元へ自動同期されません。
- JSON が不正、必要ファイルがない、形式が対応外、複数の保存形式が一致しない場合は自動修復しません。保全したコピーを別の確認用ディレクトリで、対応版アプリや明示的なレビューにより確認してください。単にファイル名を変えたり、古いバックアップを現行ファイルへ上書きして続行しないでください。

## 検証

`tests/ProfileImport.Tests.ps1` は依存ライブラリなしの合成データ用回帰テストです。Windows CI から実行します。実際のユーザープロファイルやアプリを開くことはありません。

```powershell
pwsh -NoProfile -File .\tests\ProfileImport.Tests.ps1
```

主な検証範囲: 完全バックアップ一致、元データ不変、非空/空の既存保存先拒否、重複パス/親子関係/トラバーサル/再解析ポイント/代替ストリーム拒否、読み取りハンドル、バックアップ中の追加検出、不正JSON、未来スキーマ、ステージング破損、公開直前の保存先競合、サイズ上限、失敗時のバックアップ保持。DIndexではスキーマなしの従来設定、未知の追加設定のバイト保持、既知フィールドの型も検証します。

作成時のLinux環境には PowerShell がなく、このスクリプトはその環境では実行していません。Windows CI の結果と、別途Windowsでの実ユーザー操作の受け入れ確認を区別してください。実データ移行は今回実行していません。

Windowsの代替ストリーム検出には、PowerShell 7.2以降の[Get-Item -Stream](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.management/get-item?view=powershell-7.6)を使用します。
